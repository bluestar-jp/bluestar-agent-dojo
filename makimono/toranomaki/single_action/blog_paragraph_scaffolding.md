# ブログ段落執筆テンプレート

- Purpose: 技術ブログ記事の段落を執筆するための構造テンプレート
- Scope: トピックセンテンス、根拠、トランジションの構造

## 1. 基本構造

技術ブログの段落は以下の3要素で構成される：

```text
[トピックセンテンス]
  ↓
[根拠・詳細・例]
  ↓
[トランジション（オプション）]
```

---

## 2. トピックセンテンス（Topic Sentence）

### 役割

段落の主題を1-2文で明示する。読者に「この段落は何について書かれているか」を伝える。

### パターン

#### パターンA: 問題提起型

```text
<問題>が発生する。<影響>。
```

**例**:

```text
Reactアプリケーションが遅い。ページの読み込みに3秒かかる。
```

#### パターンB: 解決策提示型

```text
<手法>を使うと<結果>。
```

**例**:

```text
React.memoを使うとレンダリング回数が半分になる。
```

#### パターンC: 状況説明型

```text
<技術/概念>は<定義>。
```

**例**:

```text
メモ化は計算結果をキャッシュする仕組みだ。
```

#### パターンD: 比較型

```text
<技術A>と<技術B>では<観点>が異なる。
```

**例**:

```text
JestとVitestではテスト実行速度が大きく異なる。
```

### 避けるべき表現

❌ 「本段落では〜を説明します」（前置き宣言）
❌ 「一般的に〜です」（安全クッション）
❌ 「これは重要です」（抽象語の空回り）

---

## 3. 根拠・詳細・例（Supporting Details）

### 役割

トピックセンテンスで示した主題を、根拠、詳細、具体例で支える。

### パターン

#### パターンA: データで裏付け

```text
<トピックセンテンス>
<測定結果/数値データ>
```

**例**:

```text
React.memoを使うとレンダリング回数が半分になる。
ベンチマークでは、1000回のレンダリングが500回に削減された。
```

#### パターンB: コード例で説明

```text
<トピックセンテンス>
<コード例>
<コードの説明>
```

**例**:

````text
React.memoを使うとレンダリング回数が半分になる。

```typescript
const MemoizedComponent = React.memo(ExpensiveComponent);
```

この例では、propsが変更されない限りExpensiveComponentは再レンダリングされない。

````

#### パターンC: 具体例で解説

```text
<トピックセンテンス>
<具体的なシナリオ>
```

**例**:

```text
メモ化は計算結果をキャッシュする仕組みだ。
フィボナッチ数列の計算では、一度計算した値を保存しておくことで、同じ値を何度も計算する無駄を省ける。
```

#### パターンD: 理由を説明

```text
<トピックセンテンス>
<なぜそうなるのか/どのような仕組みか>
```

**例**:

```text
JestとVitestではテスト実行速度が大きく異なる。
Vitestはネイティブモジュールを直接実行するため、Jestのトランスパイルステップを省略できる。
```

### 避けるべき表現

❌ 根拠なしの主張の繰り返し
❌ 同義語の言い換え連打（「シンプルです。簡単です。分かりやすいです。」）
❌ コード例だけで説明なし

---

## 4. トランジション（Transition）

### 役割

次の段落への自然な繋ぎを提供する（必須ではない）。

### パターン

#### パターンA: 次の話題を予告

```text
<段落本文>
次に、<次の話題>を見ていく。
```

**例**:

```text
React.memoを使うとレンダリング回数が半分になる。ベンチマークでは、1000回のレンダリングが500回に削減された。
次に、useMemoとの違いを見ていく。
```

#### パターンB: 因果関係で繋ぐ

```text
<段落本文>
この結果、<次の段落の内容>が必要になる。
```

**例**:

```text
Vitestはネイティブモジュールを直接実行するため高速だ。
この特性を活かすには、設定ファイルの最適化が重要になる。
```

#### パターンC: 対比で繋ぐ

```text
<段落本文>
一方、<次の段落の観点>も考慮すべきだ。
```

**例**:

```text
Jestはエコシステムが成熟しており、プラグインが豊富だ。
一方、実行速度ではVitestに劣る。
```

#### パターンD: トランジションなし

段落間の繋がりが自明な場合、トランジションは不要。

**例**:

```text
# 手順

## Step 1: 環境構築
<内容>

## Step 2: 設定ファイル作成
<内容>
```

### 避けるべき表現

❌ 「次に〜を見ていきましょう」（丁寧すぎる敬体）
❌ 「また、〜」の連続使用（接続詞の単調さ）

## 5. 段落タイプ別のテンプレート

### 5.1 導入段落（Introduction Paragraph）

**目的**: 課題とゴールを明示

**テンプレート**:

```text
[問題提起]
[影響/重要性]
[記事のゴール]
```

**例**:

```text
Reactアプリケーションが遅い。ページの読み込みに3秒かかり、ユーザーが離脱する。
本記事では、React.memoを使ったパフォーマンス最適化の手法を紹介する。ベンチマークで測定した具体的な改善効果も示す。
```

---

### 5.2 説明段落（Explanation Paragraph）

**目的**: 概念や仕組みを説明

**テンプレート**:

```text
[概念の定義]
[仕組み/原理]
[具体例]
```

**例**:

```text
メモ化は計算結果をキャッシュする仕組みだ。
関数が同じ引数で呼ばれた場合、前回の計算結果を返すことで、再計算を避ける。
フィボナッチ数列の計算では、一度計算した値を保存しておくことで、同じ値を何度も計算する無駄を省ける。
```

---

### 5.3 手順段落（Instruction Paragraph）

**目的**: 実装手順を示す

**テンプレート**:

```text
[手順の概要]
[コード例]
[コードの説明]
[注意点/ポイント]
```

**例**:

````text
まず、React.memoでコンポーネントをラップする。

```typescript
const MemoizedComponent = React.memo(ExpensiveComponent);
```

この例では、propsが変更されない限りExpensiveComponentは再レンダリングされない。
注意点として、オブジェクトや配列のpropsは参照が変わると再レンダリングされる。

````

---

### 5.4 比較段落（Comparison Paragraph）

**目的**: 複数のオプションを比較

**テンプレート**:

```text
[比較観点の提示]
[オプションAの特性]
[オプションBの特性]
[推奨事項]
```

**例**:

```text
テスト実行速度では、JestとVitestで大きな差がある。
Jestは1000テストの実行に15秒かかる。Vitestは同じテストを3秒で実行する。
大規模なテストスイートを持つプロジェクトでは、Vitestの高速性が開発体験を大きく改善する。
```

---

### 5.5 結論段落（Conclusion Paragraph）

**目的**: 要点のまとめと次のステップ

**テンプレート**:

```text
[要点の再確認]
[達成したこと]
[次のステップ/実践への呼びかけ]
```

**例**:

```text
React.memoを使うことで、レンダリング回数を半分に削減できた。
ベンチマークでは、ページの読み込み時間が3秒から1.5秒に短縮された。
実際のプロジェクトで試し、パフォーマンスの改善を体感してほしい。
```

---

## 6. 段落の長さとリズム

### 長さの目安

- **短い段落**: 1-2文、50-100文字（リズムのアクセント）
- **標準段落**: 3-4文、100-200文字（基本）
- **長い段落**: 5-6文、200-300文字（詳細な説明が必要な場合）

### リズムの作り方

```text
短い段落（問題提起）
  ↓
長い段落（詳細説明）
  ↓
標準段落（まとめ）
  ↓
短い段落（次への繋ぎ）
```

**例**:

```text
Reactアプリケーションが遅い。

パフォーマンスの問題は、不要な再レンダリングが原因だ。親コンポーネントの状態が変わるたびに、子コンポーネントも再レンダリングされる。この再レンダリングが積み重なると、ページ全体の読み込みが遅くなる。

React.memoを使うと、この問題を解決できる。propsが変わらない限り、コンポーネントは再レンダリングされない。

次に、具体的な実装手順を見ていく。
```

## 7. チェックリスト

段落執筆後、以下を確認：

- [ ] トピックセンテンスが明確か
- [ ] 根拠や具体例で主題を支えているか
- [ ] 1段落1アイデアの原則を守っているか
- [ ] 段落の長さが適切か（300文字以内）
- [ ] 前置き宣言や安全クッションがないか
- [ ] 抽象語の空回りがないか
- [ ] コード例に説明が付いているか
- [ ] 次の段落への繋がりが自然か
