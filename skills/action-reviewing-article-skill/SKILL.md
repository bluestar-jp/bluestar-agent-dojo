# Article Structure & Readability Review Skill

- Purpose: 技術ブログ記事の構造と読みやすさをレビュー
- Scope: 文章の流れ、段落間の繋がり、構成品質のチェック

## 入力形式

```json
{
  "draft_article": {
    "frontmatter": {
      "title": "記事タイトル",
      "type": "tech",
      "topics": ["react", "typescript"]
    },
    "content": "<全段落を統合したMarkdownテキスト>",
    "sections": [
      {
        "heading": "はじめに",
        "paragraphs": ["P1", "P2"]
      }
    ]
  },
  "template_type": "how-to|deep-dive|comparison|case-study|concept"
}
```

## レビュー観点

### 1. 全体構成（Structure）

#### ✅ Good

- 記事タイプに適した構成パターン
- 見出し階層が適切（H2→H3、H2の下にH4が来ない）
- 導入→本論→まとめの流れが明確

#### ⚠️ Needs Improvement

- 記事タイプが不明確
- 見出し階層が乱れている
- 導入が長すぎる/まとめがない

#### 🚫 Critical Issue

- 全体の構成が不明瞭
- 見出しと本文の内容が不一致
- タイトルと内容がずれている

### 2. 情報の流れ（Flow）

#### ✅ Good

- トップダウン構成（重要な情報が先）
- 段階的な情報開示（基礎→応用）
- 前提知識から詳細へのスムーズな移行

#### ⚠️ Needs Improvement

- 一部で情報の順序が逆転
- 唐突に詳細情報が登場
- 前提知識の説明が後回し

#### 🚫 Critical Issue

- 情報の流れが断片的
- 必要な前提知識が説明されていない
- 結論が途中で出てきて混乱

### 3. 段落構造（Paragraph）

#### ✅ Good

- 各段落に明確なトピックセンテンス
- 1段落1アイデアの原則
- 根拠や具体例で主題を支える

#### ⚠️ Needs Improvement

- トピックセンテンスが不明確な段落がある
- 1段落に複数のアイデアが混在
- 根拠や具体例が不足

#### 🚫 Critical Issue

- ほとんどの段落でトピックセンテンスがない
- 段落が単なる文の羅列
- 根拠のない主張が多い

### 4. 段落間のトランジション（Transition）

#### ✅ Good

- 段落間の繋がりが自然
- 適切な接続詞や繋ぎ言葉
- 前段落の内容を受けて次段落が展開

#### ⚠️ Needs Improvement

- 一部で段落間の繋がりが唐突
- 接続詞が不足または過剰
- トピックの切り替わりが急すぎる

#### 🚫 Critical Issue

- 段落間の繋がりがほとんどない
- 各段落が独立した島のように存在
- 読者が文脈を見失う

### 5. 文章レベル（Sentence）

#### ✅ Good

- 1文が30-40文字程度で読みやすい
- 短い文と長い文が適度に混在
- 主語と述語が明確

#### ⚠️ Needs Improvement

- 長い文が多い（50文字超）
- すべての文が同じ長さで単調
- 主語が不明確な文がある

#### 🚫 Critical Issue

- 極端に長い文が多数（80文字超）
- 一文一文が機械的で均一
- 主語と述語の対応が不明

### 6. 専門用語（Terminology）

#### ✅ Good

- 初出の専門用語を簡潔に説明
- 対象読者に合った用語レベル
- 必要に応じて用語の言い換えを提供

#### ⚠️ Needs Improvement

- 専門用語の説明が不足している箇所がある
- 同じ用語に複数の表記が混在
- 説明が冗長すぎる

#### 🚫 Critical Issue

- 専門用語が説明なしに多用
- 対象読者のレベルと用語が合っていない
- 誤った用語の使用や定義

### 7. ビジュアル構造（Visual）

#### ✅ Good

- 見出しが内容を正確に反映
- 並列情報を箇条書きで整理
- 重要な箇所に最小限の強調

#### ⚠️ Needs Improvement

- 見出しと内容がやや不一致
- リストにできる情報が文章になっている
- 強調が多すぎて重要性が不明

#### 🚫 Critical Issue

- 見出しが内容と全く合っていない
- リスト化すべき情報が長文の羅列
- 太字だらけで読みにくい

### 8. コンテンツの完全性（Completeness）

#### ✅ Good

- 導入で課題とゴールを明示
- 本論で十分な情報を提供
- まとめで要点を再確認
- 次のステップを示している

#### ⚠️ Needs Improvement

- 導入またはまとめが弱い
- 本論の一部が不十分
- 次のステップがやや不明確

#### 🚫 Critical Issue

- 導入またはまとめが欠落
- 本論の重要部分が不足
- 読者が次に何をすべきか全く不明

## レビュープロセス

### Step 1: 全体構成の確認

1. 記事タイプとテンプレートの整合性を確認
2. 見出し階層をチェック（`Grep: "^#{1,4} "` でH1-H4を抽出）
3. 必須セクション（導入、本論、まとめ）の有無を確認

### Step 2: 情報の流れの検証

1. セクションの順序が論理的か確認
2. 前提知識→詳細への流れを確認
3. トップダウン構成になっているか確認

### Step 3: 段落レベルの分析

1. 各段落のトピックセンテンスを特定
2. 1段落1アイデアの原則を確認
3. 段落の長さをチェック（300文字超は警告）

### Step 4: トランジションの評価

1. 段落間の繋がりを確認
2. 接続詞の使用状況をチェック
3. 唐突なトピック変更を検出

### Step 5: 文章品質の確認

1. 文の長さを測定（80文字超は警告）
2. 文のリズムを確認（均一性を検出）
3. 主語・述語の明確性をチェック

### Step 6: 専門用語の確認

1. 専門用語のリストアップ（`Grep`使用）
2. 初出時の説明有無を確認
3. 用語の一貫性をチェック

### Step 7: ビジュアル要素の検証

1. 見出しと内容の一致を確認
2. リスト化可能な情報を検出
3. 強調記号（**太字**等）の使用頻度をカウント

## 出力形式

```json
{
  "review_type": "structure_readability",
  "overall_quality": "good|needs_revision",
  "findings": [
    {
      "severity": "critical|high|medium|low",
      "category": "structure|flow|paragraph|transition|sentence|terminology|visual|completeness",
      "paragraph_id": "P2",
      "section": "手順",
      "issue": "段落間のトランジションが唐突。P1からP2への繋がりが不明確。",
      "suggestion": "P1の末尾に「次に、具体的な実装手順を見ていく。」等の繋ぎ文を追加。またはP2の冒頭を「まず、」で始める。",
      "example": "P1末尾に追加: 「次に、具体的な実装手順を見ていく。」"
    }
  ],
  "summary": {
    "critical_issues": 0,
    "high_issues": 2,
    "medium_issues": 5,
    "low_issues": 3,
    "total_paragraphs_reviewed": 8
  },
  "recommendations": [
    "段落P2とP3の間にトランジションを追加",
    "専門用語「メモ化」の初出時に定義を追加",
    "まとめセクションで次のステップを明示"
  ]
}
```

## 重要度の判断基準

- **critical**: 記事の理解を著しく妨げる、技術的に誤っている
- **high**: 読者が混乱する可能性が高い、構成の根本的な問題
- **medium**: 読みやすさを損なう、一部の読者が躓く可能性
- **low**: 改善すればより良くなる、細かい表現の問題

## 自己修正

### 判断が困難な場合

- コンテキストを追加確認（前後の段落を読む）
- 重要度を下げて報告
- ユーザー確認を推奨事項として追加

### 誤検知の可能性

- 記事タイプを再確認（意図的な構成の可能性）
- 対象読者を考慮（初心者向けなら詳細説明は適切）
- suggestion に「〜の可能性あり」と記載
